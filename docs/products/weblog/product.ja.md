# weblog.yamanoku.net

[English](product.md)

## 概要

weblog.yamanoku.net は、yamanoku 一人が公開するハイパーテキストである。ここでのハイパーテキストは、ページのタイトルを双方向に辿れる文書の集まりを指す。ブログ記事、ミニブログ、ブックマーク、[Cosense の yamanoku プロジェクト](https://scrapbox.io/yamanoku/) から取り込んだページを、このホストで公開する。エントリは、保存する本文の単位である。四つの種類は別のアプリにせず、このホストのエントリとして扱う。本文の正本はプレーンテキストである。表示用の HTML は正本から作る派生であり、保存形式にしない。

人は公開ページと、人間向けのフィードを読める。note の正規 URL では、所有者が足した返信も読める。返信は、そのページに置く。ActivityPub は、他のインスタンスがアクターをフォローし、活動を受け取るための仕組みである。リモートのインスタンスは `acct:yamanoku@weblog.yamanoku.net` をフォローし、このホストが配送する公開エントリを受け取れる。配送するエントリは、公開された記事、ミニブログ、ブックマークである。Cosense から取り込んだページは、所有者が種類を変えるまで、人間向けのフィードと配送に載せない。

公開ホストは `weblog.yamanoku.net` とする。書く人は所有者だけで、登録は置かない。次は、このプロダクトに含めない。

- 他のアクターをこちらからフォローすること
- 所有者以外の返信、ActivityPub の返信、Boost、お気に入り
- WebMention
- リアルタイムの共同編集
- [archives.yamanoku.net](https://archives.yamanoku.net/) からの移行
- Cosense との双方向同期
- 移行対象より後に Cosense で作られたページ。対象の定めは [Cosense からの取り込み](features/cosense-import/requirements.ja.md) にある
- 既存の Mastodon や Misskey への投稿
- 見た目

## 背景と解決する課題

### 背景

[archives.yamanoku.net](https://archives.yamanoku.net/) は、yamanoku が書いてきた過去の記事を集めた静的なアーカイブである。生成には Astro を使う。2026-11-01 にページを開いた。過去の記事やログを収集したページであり、移行時のリンク修正を除き内容は更新していない、とページ自身が説明していた。この静的アーカイブを広げる案は採らない。閲覧とフィードには、この静的サイトで足りる。静的なファイルだけでは、受信箱、署名、フォロワーへの配送を持てない。ブラウザと CLI からの同時更新も持てない。

[Cosense の yamanoku プロジェクト](https://scrapbox.io/yamanoku/) は、タイトルでつながったページを既に持っている。2026-11-01 にプロジェクトのページを開くと、タイトルがリンクとして並んでいた。Cosense は、このホストの ActivityPub アクター、リモートフォロー、所有者だけの書き込みを提供しない。本文の正本を Cosense のままにはしない。

### 解決する課題

所有者は、記事、ミニブログ、ブックマーク、リンクされたメモを別々の場所に置いている。静的アーカイブはリモートフォローを受けられず、ブラウザと CLI の両方からの書き込みも受けられない。Cosense のページはタイトルで辿れ、このホストのアクターとしては公開されない。

アカウントを持たない閲覧者には、このホストで公開エントリを読み、タイトルを辿る場所が無い。人間向けのフィードを購読する場所も無い。

リモートの ActivityPub インスタンスには、フォローするアクター `acct:yamanoku@weblog.yamanoku.net` が無い。このホストが配送する公開エントリも受け取れない。

## ターゲットエンドユーザー

### 所有者 yamanoku

- **特性:** このホストに書く唯一の人である。ブラウザと CLI を使う。取り込みの要件が定める、作成済みの Cosense ページをこのホストへ移す。
- **抱える課題:** 記事とリンクされたページが別の場所にある。リモートフォローと、所有者だけの書き込みを、一つのホストで持てない。
- **利用文脈:** エントリを作り、更新し、公開し、削除する。取り込みの要件が定める作成済みページを、このホストへ移す。移したあと、所有者は Cosense の公開プロジェクトを更新しない。プログラムは、所有者の CLI 資格で同じ書き込み経路を呼べる。

### 未認証の閲覧者

- **特性:** アカウントを持たずに公開サイトを開く人である。
- **抱える課題:** ログインせずに、このホストの公開エントリを読めない。タイトルを双方向に辿れない。人間向けのフィードも購読できない。
- **利用文脈:** 公開ページを読み、人間向けのフィードを購読する。

### リモートの ActivityPub インスタンス

- **特性:** 他のインスタンスのアクターをフォローし、署名された活動を受け取るサーバである。
- **抱える課題:** このホストのアクターをフォローできない。このホストが配送する公開エントリも受け取れない。
- **利用文脈:** アクターをフォローし、配送を受け取り、フォローを取り消す。エントリは書かない。

## 提供価値

### 一つの公開ハイパーテキスト

- **対象:** 所有者と、未認証の閲覧者
- **内容:** ブログ記事、ミニブログ、ブックマーク、取り込んだページを一つのホストに置く。本文のタイトル参照は、双方向に辿れる。
- **提供理由:** 所有者は、一つのサイトと、Cosense と同じ双方向のタイトル参照を求めている。静的アーカイブは過去の記事を集めたものである。Cosense は、このホストの公開サイトではない。

### 人間向けのフィード

- **対象:** 未認証の閲覧者
- **内容:** 人間向けに公開したエントリのフィードを出す
- **提供理由:** 所有者は、人間向けのフィードを求めている。リモートのインスタンスへの配送は、別の経路である。

### リモートフォロー

- **対象:** リモートの ActivityPub インスタンスと、フォローされたい所有者
- **内容:** `acct:yamanoku@weblog.yamanoku.net` をフォローでき、このホストが配送する公開エントリを受け取れる
- **提供理由:** 静的アーカイブはフォローを受信できない。フォロワーへ配送もできない。所有者は、他のインスタンスがこのホストをフォローできるようにしたい。

### 所有者だけの書き込み

- **対象:** 所有者
- **内容:** ブラウザと CLI から、エントリの作成、更新、公開、削除ができる
- **提供理由:** 書く人は所有者一人である。登録は置かない。書き込みの経路は、所有者が指定したブラウザと CLI である。

### 後から外せる実行環境

- **対象:** 所有者
- **内容:** アプリを動かす新規の費用をゼロ円に保ち、実行に使う部品を後から差し替えられるようにする。所有者が取り出せる項目と、それを復元できるときだけ保存方式を採る規則は、[移設](features/relocation/requirements.ja.md) にある。
- **提供理由:** 所有者は、最初の実行場所を Cloudflare の無料枠とし、その部品を後から外せるようにしたい。ドメイン名の登録維持費はレジストリへ払う費用であり、ゼロ円の対象外である。既存の Gyazo アーカイブの保存量のうち、月 10 GB を超える分も対象外である。

## 成功の定義

次がすべて成り立つとき、プロダクトは成功している。

- 所有者は、ブラウザと CLI から weblog.yamanoku.net へ記事、ミニブログ、ブックマークを公開できる。取り込みの要件が定める作成済みページも、同じホストへ移せる。
- ログインしていない人が、公開エントリを読み、タイトルのリンクを双方向に辿れる。人間向けのフィードも読める。note の正規 URL では、所有者が足した返信も読める。返信はフィードに載せず、配送もしない。
- リモートのインスタンスが `acct:yamanoku@weblog.yamanoku.net` をフォローし、このホストが配送する公開エントリを受け取れる。
- Cosense から取り込んだページは、所有者が種類を変えるまで、人間向けのフィードに載せない。リモートへの配送にも載せない。
- アプリを動かす新規の費用はゼロ円である。無料枠を超える処理は失敗するか、翌日の 00:00 UTC まで待つ。アプリ自身は有料プランへ移らない。

## プロダクト開発を進める上での指針

- 書く人は所有者一人とする。登録 API は置かない。
- 本文の正本はプレーンテキストとする。表示用の HTML は、その本文から作る。
- 公開したあとのホスト名と、公開済みの ActivityPub 識別子は変えない。ホスト名を変えると、リモートのサーバが保存した `acct:` とオブジェクトの識別子が切れる。DNS の提供元は差し替えられる。ホスト名の HTTPS が、このアプリへ解決している必要がある。
- カスタムドメインは、Free プランのゾーンへ付ける。2026-10-02 更新の [Workers の料金](https://developers.cloudflare.com/workers/platform/pricing/) には、追加料金が書かれていない。2026-10-29 更新の [Workers の制限](https://developers.cloudflare.com/workers/platform/limits/) にも、追加料金は書かれていない。上限は、ゾーンあたり 100 件である。ゾーンは Free プランのままである。Pro 以上のゾーンプランは契約しない。
- エントリの規則は Cloudflare の SDK を前提にしない。実行に使う部品は差し替えられるようにする。
- 新規の実行費用をゼロ円に保つことを、無料枠に収まらなくなった処理を続けることより優先する。その処理は失敗させるか、翌日の 00:00 UTC まで待つ。アプリ自身は有料プランへ移らない。
- Workers Paid は、利用が無くても月額 5 ドルである。出典は 2026-10-02 更新の [Workers の料金](https://developers.cloudflare.com/workers/platform/pricing/) である。最初からは契約しない。測定の前にも契約しない。
- HTTP 署名の生成または検証が、1 回の CPU 時間の無料枠を超えるときは、計算量を減らして無料枠で運用する。この理由で、有料プランは契約しない。収まるまで、その処理は実行しない。
- D1 の無料枠は、1 日 500 万行の読み取りと、アカウント合計 5 GB を含む。この数は、同じ料金ページの D1 の表に書いてある。更新日は 2026-10-02 である。
- ドメイン名の登録維持費は、ゼロ円の対象外である。既存の Gyazo アーカイブの保存量のうち、月 10 GB を超える分も対象外である。
- Cosense から取り込んだページは、記事、ミニブログ、ブックマークへ自動では分類しない。フォロワーへ一括では配送しない。
- 公開 URL と活動 ID の形は、この版で固定する。連合の契約を後から足すと、公開後のホストが変わる。実装の順番は、別の決まりにしない。
- 既存の Mastodon や Misskey へ投稿する案は採らない。リモートフォローは、その案でも満たせる。記事、ブックマーク、未作成タイトルへの双方向リンクは、一つの行テキストから出せない。
- 画面のフレームワークは Svelte とする。ORM は `void/db` とする。保存の第一アダプタは D1 のままである。D1 の 500 MB、1 日の行数、1 回 50 クエリを超える処理は採らない。

## SLA・SLI・SLO

### SLA

設けない。閲覧者とリモートのインスタンスへ、可用性を保証しない。配送時刻も保証しない。無料枠を超えた処理は失敗するか、翌日まで待つ。アプリ自身は有料プランへ移らない。これは所有者が決めた。可用性を保証するには、このプロダクトが買わない有料の容量が要る。

### SLI・SLO

数値の目標は設けない。運用の規則は、可用性の割合を達成することではない。無料枠を使い切った処理は、失敗させるか待つ。配送の成功率も、割合の目標にはしない。

HTTP 署名の生成または検証が、1 回の CPU 時間の無料枠に収まるかは、測っていない。この未測を、現在の SLO にはしない。超えるときの扱いは、上の指針にある。

## 未決事項

次は、この目的の外である。それぞれを受け持つ Requirements で決める。未決の選択と、決めた暫定の扱いは、その Requirements に書いてある。

- リンク以外の Cosense 記法の描画は、[公開閲覧](features/public-reading/requirements.ja.md) にある
- 取り出しファイルの物理形式は、[移設](features/relocation/requirements.ja.md) にある

目的、利用者、提供価値は変えない。
