# クリップ

[English](requirements.md)

## このドキュメントについて

所有者は、Worker アプリケーションとは別のパッケージから、記事を一つ、ツイート（X の投稿）を一つ、または YouTube の動画を一つクリップする。所有者は、これをブックマークにすると選んだ。外部 URL と、プレーンテキストのコメントである。パッケージは、フィクスチャからそのペイロードを組み立て、所有者が選んだ既存の CLI トークンで提出する。親プロダクトは [weblog.yamanoku.net](../../product.ja.md) である。

### スコープ

- Worker アプリケーションとは別のクリップ用パッケージ
- フィクスチャが名付ける、記事一つ、ツイート一つ、YouTube 動画一つ
- その対象のブックマークのペイロード。タイトル、本文、公開状態、URL
- そのペイロードを、所有者の CLI トークンで提出すること
- そのトークンが無い提出はエントリを保存しない、という規則

### スコープ外

- 新しいエントリ種別、新しいフィード、新しい ActivityPub オブジェクト種別。種別、プレーンテキストの本文、ブックマーク URL の項目は [所有者の書き込み](../owner-writing/requirements.ja.md) にある。
- 既存の Mastodon や Misskey への投稿。親プロダクトが既に対象外としている。
- 記事、X、YouTube のライブ取得。oEmbed の資格情報と、字幕のダウンロードを含む。
- 作者、字幕、サムネイル、動画 ID、oEmbed の文書。
- URL を記事、ツイート、YouTube 動画のどれかに分類すること。対象名はフィクスチャが持つ。
- パッケージをブラウザのストアへ公開すること。
- Access を外したあとのブラウザ認証。その問いは [所有者の書き込み](../owner-writing/requirements.ja.md) に残す。この機能は、所有者が拡張機能のために選んだ CLI トークンを使う。
- 新しく有料の Cloudflare 実行環境を足すこと。
- 他のアクターのフォロー、返信、ブースト、お気に入り、WebMention。

## ユーザーストーリー

### 気になった対象をクリップする

所有者として、別パッケージから記事一つ、ツイート一つ、または YouTube 動画一つをクリップしたい。それによって、このホストは他のエントリと同じ書き込み規則で、それをブックマークとして保存する。

**受け入れ条件:**

Scenario: 記事のフィクスチャがブックマークの項目を持つ場合、パッケージはブックマークのペイロードを返す

- Given: フィクスチャの対象名は `article` である。空でない外部 URL、タイトル、プレーンテキストの本文、公開状態 `public` を含む。パッケージはネットワークを取得しない。
- When: 所有者がそのフィクスチャを変換する。
- Then: 結果は対象 `article` を名付ける。ペイロードの種別は `bookmark` である。タイトルは、所有者の書き込みの正規化を経たフィクスチャのタイトルである。本文はフィクスチャの本文である。公開状態は `public` である。ブックマーク URL はフィクスチャの URL であり、本文とは別である。本文にその URL は加わらない。

Scenario: ツイートのフィクスチャがブックマークの項目を持つ場合、パッケージはブックマークのペイロードを返す

- Given: フィクスチャの対象名は `tweet` である。空でない外部 URL、タイトル、プレーンテキストの本文、公開状態 `public` を含む。パッケージはネットワークを取得しない。
- When: 所有者がそのフィクスチャを変換する。
- Then: 結果は対象 `tweet` を名付ける。ペイロードの種別は `bookmark` である。タイトル、本文、公開状態、ブックマーク URL は、記事のクリップと同じ規則に従う。本文に URL は加わらない。

Scenario: YouTube のフィクスチャがブックマークの項目を持つ場合、パッケージはブックマークのペイロードを返す

- Given: フィクスチャの対象名は `youtube` である。空でない外部 URL、タイトル、プレーンテキストの本文、公開状態 `draft` または `public` を含む。パッケージはネットワークを取得しない。
- When: 所有者がそのフィクスチャを変換する。
- Then: 結果は対象 `youtube` を名付ける。ペイロードの種別は `bookmark` である。タイトル、本文、公開状態、ブックマーク URL は、記事のクリップと同じ規則に従う。本文に URL は加わらない。

Scenario: CLI トークンでペイロードを提出する場合、ホストはブックマークを保存する

- Given: `article`、`tweet`、`youtube` の変換結果がブックマークのペイロードを持つ。提出は所有者の CLI トークンを示す。エントリ一覧の長さは決まっている。
- When: 所有者がその結果を提出する。
- Then: エントリ一覧にブックマークが一つ増える。保存される項目は、種別 `bookmark`、ペイロードのタイトル、ペイロードの本文、ペイロードの公開状態、ペイロードのブックマーク URL である。トークンは保存される項目ではない。

Scenario: 同じフィクスチャを二度変換する場合、ペイロードの内容は一致する

- Given: 一つのフィクスチャが `article`、`tweet`、`youtube` のいずれかを名付け、ブックマークの項目を含む。
- When: 所有者がそのフィクスチャを二度変換する。
- Then: 二つの結果は、同じ対象名と同じブックマークのペイロードを持つ。

Scenario: 対象が三つ以外の場合、パッケージはペイロードを返さない

- Given: フィクスチャが `source` を欠く。または `source` が `article`、`tweet`、`youtube` 以外の文字列である。
- When: 所有者がそのフィクスチャを変換する。
- Then: 結果は対象を名付けず、ブックマークのペイロードを持たない。その後の提出はエントリを保存しない。

Scenario: 所有者の書き込みが拒否する項目の場合、パッケージはペイロードを返さない

- Given: フィクスチャは三つの対象のいずれかを名付ける。
- When: 正規化後のタイトルが空である、外部 URL が無い、公開状態が `public` で本文が空文字列である、または公開状態が `draft` でも `public` でもない。
- Then: 結果は対象を名付け、ブックマークのペイロードを持たない。拒否は、タイトルの欠如、ブックマーク URL の欠如、公開本文が空であること、公開状態が不正であることのいずれかを区別する。その後の提出はエントリを保存しない。

Scenario: 下書きのクリップの本文が空の場合、パッケージは空の本文のブックマークを返す

- Given: フィクスチャは三つの対象のいずれかを名付け、タイトルと外部 URL を持ち、公開状態は `draft`、本文は空である。
- When: 所有者がそのフィクスチャを変換する。
- Then: ペイロードの種別は `bookmark`、公開状態は `draft`、本文は空文字列である。ブックマーク URL は本文とは別のままである。

Scenario: 提出に CLI トークンが無い場合、ホストはエントリを保存しない

- Given: ブックマークのペイロードがある。提出は CLI トークンを示さない。
- When: パッケージにそのペイロードの提出を求める。
- Then: エントリ一覧の長さは変わらない。拒否は、所有者の確認が無いことである。トークンの値はエントリへ書かれない。

## 機能要件

### フィクスチャを変換する

**概要:** クリップのパッケージは、呼び手が既に持っているフィクスチャを読む。`article`、`tweet`、`youtube` については、タイトル、本文、公開状態、URL からブックマークのペイロードを一つ組み立てる。それ以外の項目はコピーしない。

**入力:** フィクスチャのオブジェクト。対象名は `article`、`tweet`、`youtube` である。ブックマークの項目は `url`、`title`、`body`、`visibility` である。パッケージは、それらをネットワークから取得しない。

**出力:** 対象を名付ける結果と、ブックマークのペイロード、または拒否とペイロードの不在。

#### 適用する条件

##### 対象

対象は `article`、`tweet`、`youtube` である。`tweet` は X の投稿一つである。`youtube` は YouTube の動画一つである。`article` はウェブの記事一つである。対象名の比較は大文字と小文字を区別する。それ以外の名前、欠いた名前、文字列でない名前は、三つの外である。三つの対象は、同じ四つの項目を使う。

##### 種別

所有者は `bookmark` を選んだ。所有者の書き込みは、ブックマークを外部 URL とコメントと定め、その URL を本文とは別に保存する。

##### 抽出する項目

所有者は、記事、ツイート、YouTube 動画に、同じ四つの項目を選んだ。

ペイロードのタイトルは、所有者の書き込みの正規化を経たフィクスチャのタイトルである。両端の空白を除き、連続する空白を一つの空白にする。ペイロードの本文は、フィクスチャの本文が文字列ならその文字列であり、欠けるときは空文字列である。パッケージは本文を書き換えず、URL を本文へ入れない。ペイロードの公開状態は、所有者がフィクスチャに指定した `draft` または `public` である。ペイロードのブックマーク URL は、フィクスチャの `url` 文字列であり、本文とは別に保存する。

対象名はエントリの項目ではない。

##### 繰り返す変換

同じフィクスチャの二度の変換は、同じ内容の結果を返す。パッケージは、結果へ時刻も乱数も足さない。

#### 例外ケースでの振る舞い

##### 三つ以外の対象

結果は対象を名付けず、ペイロードを含まず、拒否は `unknown_source` である。

##### ホストが拒否するタイトル、URL、本文、公開状態

結果は対象を名付け、ペイロードを含まない。正規化後のタイトルが空なら `missing_title` である。URL が無い、文字列でない、または両端の空白を除くと空なら `missing_bookmark_url` である。公開状態 `public` で本文が空文字列なら `empty_body` である。空白だけの本文は空ではない。公開状態が `draft` でも `public` でもなければ `invalid_visibility` である。これらの名前は、同じ場合の所有者の書き込みの拒否と一致する。本文が空の下書きは、本文が空文字列のペイロードである。

パッケージが返す拒否は一つである。確認の順は、公開状態、タイトル、URL、公開の空本文である。

### クリップ結果を提出する

**概要:** ブックマークのペイロードを、所有者の CLI トークンとともに提出すると、そのブックマークがエントリ一覧へ加わる。書き込みのホスト側の面は、所有者の書き込みの作成のままである。この機能は書き込みの経路を足さない。

**入力:** クリップ結果、CLI トークン、現在のエントリ一覧。

**出力:** ブックマークが一つ増えたエントリ一覧、または同じ一覧と拒否。

#### 適用する条件

##### CLI トークン

所有者は、拡張機能の証明として既存の CLI トークンを選んだ。プロダクトは、プログラムがその資格情報で所有者の書き込みを呼ぶことを既に認めている。パッケージはトークンを発行しない。Access を置き換えない。パスキーを採用しない。

提出は、トークンを空でない文字列として示す。保存されるブックマークはトークンを含まない。

##### 書く項目

増えるエントリは、種別 `bookmark`、ペイロードのタイトル、ペイロードの本文、ペイロードの公開状態、ペイロードのブックマーク URL を持つ。それ以外の項目は増えない。

##### ホストの経路は足さない

この機能は経路もフォームも二つ目のデータベースも足さない。ホストへ残す作成は、[所有者の書き込み](../owner-writing/requirements.ja.md) の作成のままである。

#### 例外ケースでの振る舞い

##### 未確認の提出

トークンが無い提出、または空でない文字列ではないトークンの提出は、何も保存しない。エントリ一覧の長さは変わらない。拒否は `unauthorized` である。

##### ペイロードの無い結果

トークンがあり、ペイロードの無い結果の提出は、何も保存しない。拒否は `no_payload` である。

## データ要件

### 必要なデータ

- **クリップのフィクスチャ:** 対象を一つ名付ける。名前は `article`、`tweet`、`youtube` である。`url`、`title`、`body`、`visibility` を持つ。この機能は、変換が返ったあとフィクスチャを保持しない。
- **ブックマークのペイロード:** 種別 `bookmark`、正規化したタイトル、プレーンテキストの本文、公開状態 `draft` または `public`、本文とは別の外部 URL。
- **CLI トークン:** 提出のときに示す資格情報。ブックマークの一部ではなく、提出が返ったあとパッケージはそれを保持しない。
- **エントリ:** 呼び手のエントリ一覧へ加わるブックマーク。ホストのエントリは、[所有者の書き込み](../owner-writing/requirements.ja.md) が定めたエントリのままである。

### データ間の関係

一回の変換は、一つのフィクスチャを読み、一つの結果を返す。ペイロードを持つ結果は、一つのブックマークを指す。ブックマーク URL は、そのブックマークの項目であり、本文とは別である。

### 個人情報

フィクスチャは、所有者が見たページ、投稿、動画の文言を含みうる。その文言が人の名前を含むこともある。公開のブックマークは、所有者の書き込みにある個人情報の規則に従い、認証なしで読める。下書きの本文は所有者にとどまる。CLI トークンは所有者を識別し、保存されるブックマークには現れない。

## 依存する外部サービス

なし。パッケージは X、YouTube、ブラウザのストア、新しい Cloudflare の製品を呼ばない。CLI トークンは、所有者の書き込みが既に使う資格情報である。新しいサービスではない。

## セキュリティ上の留意事項

パッケージは、CLI トークンをブックマークへも、リポジトリへも、提出が返ったあとの保持へも置かない。ブックマークのペイロードそのものは資格情報ではない。

トークンの無い提出は何も保存しない。パッケージは、フィクスチャを Mastodon、Misskey、その他のサーバへ投稿しない。

## 未決事項

なし。所有者は、種別 `bookmark`、項目としてのタイトル、本文、公開状態、URL、既存の CLI トークンを選んだ。Access を外したあとのブラウザ認証は、[所有者の書き込み](../owner-writing/requirements.ja.md) の未決のままである。この機能はそれを決めない。
