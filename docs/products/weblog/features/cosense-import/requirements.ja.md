# Cosense からの取り込み

[English](requirements.md)

## このドキュメントについて

所有者は、CLI から公開プロジェクトのページをこのホストへ取り込む。新しいページは公開の page として保存する。配送はしない。後の実行は、ローカルの本文が最後の取り込みと一致し、ソースが新しいときだけ本文を置き換える。ローカル編集は報告し、その本文は残す。

親プロダクトは [weblog.yamanoku.net](../../product.ja.md) である。書き込みは [所有者の書き込み](../owner-writing/requirements.ja.md) の検証と、エントリと辺の同じ更新境界を使う。

### スコープ

- 公開プロジェクト `https://scrapbox.io/yamanoku/` を読む CLI のバッチ
- 未保存の Cosense ページを、公開の page として作る
- 終わっていない一覧の続きと、終わったあとの再確認
- 一致した本文の置き換え、または Cosense のページ ID を報告してローカル編集を残す
- ソースまたは無料の書き込み枠が次のページを受け付けないときの待機と再試行
- Gyazo の URL と `scrapbox.io/files` の URL を、本文中の文字列のまま残す

### スコープ外

- 所有者の手作業による作成、更新、削除、ブラウザ認証、CLI トークンの規則。この機能は、所有者の書き込みが発行済みの CLI トークンを使う
- 取り込んだページを article、note、bookmark に振り分けること。種類を変えるのは、その後の所有者の書き込みである
- 活動の送信、ActivityPub のアクター、Follow、署名
- 人間向けフィード、タイトル一覧、空ページの HTML、Gyazo 画像のバイト列。これらは [公開閲覧](../public-reading/requirements.ja.md) が決める
- 画像やファイルのバイナリの複製と、バケット `gyazo-archives` へのアップロード
- `archives.yamanoku.net` の記事の取り込み
- Cosense へ戻す双方向の同期
- リンク以外の Cosense 記法を HTML にする順序。辺の抽出は、所有者の書き込みが既に定める
- 画面のフレームワークと ORM
- ローカル編集の上へ、新しい Cosense の本文を書く手順。この機能がそれを行わないことは、下の未決事項に書く

## ユーザーストーリー

### 新しいページを取り込む

所有者として、公開の Cosense ページをこのホストの page にしたい。それによって、本文とタイトルのリンクをここへ置き、フィードと配送には載せない。

**受け入れ条件:**

Scenario: ページが未保存の場合、公開の page を一つ作る

- Given: CLI トークンは有効である。公開プロジェクトに、ページ ID とタイトルと行テキストを持つページがある。そのページ ID を持つエントリは無い。取得した本文は空ではない。
- When: 所有者が取り込みを実行する。
- Then: エントリが一つできる。種類は page、公開状態は public である。不変 ID は新しく、Cosense のページ ID ではない。正規 URL は `https://weblog.yamanoku.net/e/{id}` である。Cosense のページ ID はそのエントリに保存する。本文は取得したプレーンテキストであり、先頭行がタイトルと一致しても先頭行は残る。ブラケットの文字は変えない。このエントリは配送対象ではない。この実行は活動を送らない。

Scenario: 同じページを再び保存する場合、二つ目のエントリは作らない

- Given: その Cosense のページ ID を持つエントリが既にある。本文は最後に取り込んだ本文と一致する。ソースの更新時刻は、その取り込みで保存した時刻より新しくない。
- When: 所有者が取り込みを実行する。
- Then: 本文、タイトル、辺、種類、公開状態は変えない。不変 ID も変えない。二つ目のエントリは作らない。そのページ ID は衝突としては報告しない。

### 一覧の続きと再確認

所有者として、長い取り込みを中断のあとから続けたい。それによって、再実行は最初からやり直さず、終わった取り込みは後から新しいソースを拾える。

**受け入れ条件:**

Scenario: 一覧の走査が終わっていない場合、次の実行は完了したページの続きから行う

- Given: 走査は完了した Cosense のページ ID を記録し、一覧を終えていない。完了したページ ID のエントリは保存済みである。
- When: 所有者が取り込みを再び実行する。
- Then: 実行はその記録したページ ID の続きから行う。この走査で完了したページは、再び取得しない。保存済みのエントリは残る。プロジェクト全体を、このホストへの一つの要求の中では取り込まない。

Scenario: 一覧の走査が終わっている場合、次の実行は一覧の先頭から確認する

- Given: 直前の走査は一覧を終えている。保存済みの一つのページは、ソースの更新時刻が新しい。現在の本文は、最後に取り込んだ本文と一致する。取得した本文は空ではない。
- When: 所有者が取り込みを再び実行する。
- Then: 実行は一覧の先頭から読み、置き換えの規則を適用する。そのページの本文は置き換わる。不変 ID は維持する。本文とソース時刻が置き換えを求めないページは、そのまま残す。

Scenario: ソースが待機を求めた場合、同じページを再試行する

- Given: 一覧かページ本文の要求が、待機を求める応答を返す。応答は `Retry-After` 付きの HTTP 429、ヘッダの無い HTTP 429、5xx のいずれかである。
- When: 所有者の取り込みがその応答を受け取る。
- Then: コマンドは同じ要求を再試行する。`Retry-After` 付きの 429 は、そのヘッダの待ち時間に従う。ヘッダの無い 429 と 5xx は、60 秒待つ。この 60 秒は、成功した取得どうしの間隔ではない。ページは飛ばさない。アプリは有料プランへ移さない。

Scenario: 無料の書き込み枠が次のページを受けられない場合、枠が戻るまで待つ

- Given: 次のページの書き込みが、1 日の無料の書き込み枠に収まらない。または、その枠を使い切ったため書き込みが拒否される。
- When: 取り込みがそのページを保存しようとしたとき、または保存が拒否されたとき。
- Then: そのページは完了として記録しない。保存済みのページは残る。拒否された書き込みでは、エントリと辺は直前のままである。実行は 00:00 UTC まで待ち、その後は記録したページ ID の続きから行う。アプリは有料プランへ移さない。

### ローカル編集を残す

所有者として、手元で編集したページを、Cosense に新しい複製があっても残したい。それによって、取り込みは二つの本文のどちらを採るかを決めない。

**受け入れ条件:**

Scenario: ローカルの本文が最後の取り込みと違う場合、新しいソースは入れない

- Given: エントリはその Cosense のページ ID を持つ。現在の本文は、最後に取り込んだ本文と違う。ソースには別の本文があり、その更新時刻は新しいことがある。
- When: 所有者が取り込みを実行する。
- Then: 現在の本文、タイトル、辺、種類、公開状態は残す。新しいソースの本文は保存しない。最後に取り込んだ本文は、前の写しのままである。コマンドは、その Cosense のページ ID をローカル編集として報告する。二つ目のエントリは作らない。

Scenario: 一致した本文でソースが新しい場合、テキストを置き換える

- Given: 現在の本文は、最後に取り込んだ本文と一致する。ソースの更新時刻は新しい。取得した本文は空ではない。所有者は、種類または公開状態を既に変えていることがある。
- When: 所有者が取り込みを実行する。
- Then: タイトルと本文は、取得したタイトルとプレーンテキストになる。辺は、その本文から同じ更新で作り直す。種類、公開状態、bookmark の URL、Cosense のページ ID、不変 ID は維持する。最後に取り込んだ本文は、いま保存した本文になる。比較用のソース更新時刻は、いま読んだソースの時刻になる。そのページ ID はローカル編集としては報告しない。

Scenario: 公開の取り込みの本文が空の場合、そのページは拒否され、走査は続く

- Given: 取得した本文は空文字である。結果として残る公開状態は public である。対象には、新しいページと、public のままになる更新が含まれる。
- When: 所有者が取り込みを実行する。
- Then: 作成はエントリを保存しない。更新は、直前の本文と辺を残す。この拒否はローカル編集としては報告しない。認証の失敗でもない。コマンドは、その Cosense のページ ID を空の本文による拒否として報告する。走査は次のページへ続く。空白だけの本文は空にしない。

### ファイルの URL を本文に残す

所有者として、Gyazo と Cosense のファイル URL を文字列のままにしたい。それによって、取り込みはそれらのファイルを二重に持たない。

**受け入れ条件:**

Scenario: 本文に Gyazo または scrapbox.io のファイル URL がある場合、URL 文字列を残す

- Given: 取得したプレーンテキストに、`i.gyazo.com` の URL、`gyazo.com` の URL、または `scrapbox.io/files` の URL がある。
- When: 所有者が取り込みを実行し、そのページが保存される。
- Then: 保存した本文には、その URL 文字列が残る。ホストはバケット `gyazo-archives` へバイト列をアップロードしない。`scrapbox.io/files` のオブジェクトは複製しない。URL を囲むブラケットは、取得したときのままである。

Scenario: scrapbox.io のファイル URL が後から公開でなくなった場合、この機能は複製を持たない

- Given: 保存した本文に `scrapbox.io/files` の URL がある。その URL は後から非公開になるか、期限が切れる。
- When: 閲覧者がそのエントリを開く。
- Then: この機能は、その URL に対する保存済みファイルを持たない。エントリの本文には、その URL 文字列が残る。

## 機能要件

### 取り込んだページを書く

**概要:** Cosense のページ一つは、所有者の書き込みと同じ検証を通ってエントリ一つになる。その検証を省く経路では保存しない。

**入力:** 有効な CLI トークン、Cosense のページ ID、タイトル、取得した行テキスト。

**出力:** 保存したエントリ、または拒否。拒否のとき、直前のエントリと辺は変えない。

#### 適用する条件

##### どのプロジェクトのどのテキストか

取り込み元は、公開プロジェクト `https://scrapbox.io/yamanoku/` だけである。一覧は `https://scrapbox.io/api/pages/yamanoku` である。一覧の要素に本文の行は無い。本文は `https://scrapbox.io/api/pages/yamanoku/{title}/text` のプレーンテキストである。ブラケットは変換しない。

2026-11-01 に、その一覧の `count` は 7651 だった。件数は増える。この数は上限ではない。プロジェクト全体を、このホストへの一つの要求の中では取り込まない。保存するページは、それぞれ別の確定した書き込みである。

##### 作成が置く項目

作成は種類を page、公開状態を public にする。不変 ID と正規 URL は、所有者の書き込みに従う。Cosense のページ ID を保存し、エントリのあいだで一意にする。本文は取得した行テキストであり、先頭行がタイトルと一致しても残す。bookmark の URL は空である。このエントリは配送対象ではない。したがって publishedAt は無く、この機能は活動を送らない。

エントリの作成時刻は、作成が確定した時刻である。エントリの更新時刻は、後の書き込みが確定した時刻である。これらの時刻を、Cosense の時刻では置き換えない。ソースの更新時刻は、これらの横に保存する。後のソースが新しいかどうかの判定にだけ使う。

最後に取り込んだ本文は、この機能がそのページで最後に確定した行テキストである。

##### 後の取り込みが維持する項目

成功した置き換えは、取得したタイトルと本文を書き、辺を同じ更新で作り直す。種類、公開状態、bookmark の URL、Cosense のページ ID、不変 ID は変えない。タイトルの変更は、所有者の書き込みのリネーム規則に従う。この機能は配送済みの記録を消さない。他のエントリの本文も変えない。

この取り込み以外の所有者の書き込みも、Cosense のページ ID を残す。その定めは所有者の書き込みにある。この機能はエントリを削除しない。所有者がエントリを削除したあと、同じ Cosense のページ ID を再び取り込むと、新しい不変 ID のエントリを作る。

#### 例外時の振る舞い

##### CLI トークンを確認できない

有効な CLI トークンの無い実行は、何も保存しない。完了したページの記録も進めない。拒否は、確認できない所有者の書き込みと同じである。

##### 本文が空である

空の本文は空文字である。空白だけは空にしない。空の本文で public になる作成は、エントリを保存しない。空の本文のまま public になる更新は、直前の本文と辺を残す。そのページは、ローカル編集ではなく、空の本文による拒否として報告する。走査は次のページへ続く。

##### 保存が確定しない

書き込みが確定しないとき、エントリと辺は直前のままである。そのページは完了として記録しない。無料枠を使い切った拒否は、00:00 UTC まで待つ。所有者が見る拒否は、認証の失敗と区別できる。アプリは有料プランへ移さない。

### 走査、再試行、再開

**概要:** CLI はプロジェクトの一覧を辿る。終わっていない走査は続く。終わった走査は、先頭から再び実行できる。

**入力:** 所有者が CLI から取り込みを開始する。

**出力:** 保存したページ、続いたまたは最初から始めた走査、下で定めるページ ID の報告。

#### 適用する条件

##### 一覧の順序

走査はプロジェクトの一覧に従う。一つの一覧応答が残りを含まないとき、次の一覧要求はその応答の続きから行う。続きには、`search/titles` の応答ヘッダ `X-Following-Id` を使う。ページはその一覧の順に扱う。

書き込みが確定したページは、現在の走査の完了として記録する。記録するのは Cosense のページ ID である。

##### 終わっていない走査と終わった走査

走査が終わっていないあいだ、次の実行は最後に完了したページ ID の続きから行う。それらの完了したページは再び取得しない。

走査が終わっているとき、次の実行は一覧の先頭から読み、置き換えと報告の規則を適用する。既に保存した Cosense のページ ID に対して、二つ目のエントリは作らない。

#### 例外時の振る舞い

##### ソースが再試行を求める

`Retry-After` 付きの HTTP 429 は、そのヘッダのあいだ待ち、同じ一覧要求または同じページ本文を再試行する。ヘッダの無い HTTP 429 と、すべての 5xx は、60 秒待って同じ要求を再試行する。この待ちは、成功した取得のあいだには入れない。再試行が成功する前に、そのページを完了としては記録しない。アプリは有料プランへ移さない。

##### 一つのページを取得できない

一つのページ本文の要求が、429 と 5xx 以外のステータスで失敗したとき、そのページの新しい本文は保存しない。既存のエントリも削除しない。そのページは完了として記録しない。コマンドは Cosense のページ ID を報告する。走査は次のページへ続く。ソースがもう持たないページも、これに含める。

##### 一覧そのものが拒否される

一覧の要求が、429 と 5xx 以外のステータスで失敗したとき、実行は止まる。新しいページを完了にはしない。終わっていない走査の位置は、失敗の前のまま残す。

### 書かなかったページを報告する

**概要:** 所有者は、書かなかった Cosense のページ ID と、その理由を見る。その報告にページの本文は含めない。

**入力:** 走査が確定しなかったページの結果。

**出力:** Cosense のページ ID と、下のどの結果か。

#### 適用する条件

##### ローカル編集

現在の本文は、最後に取り込んだ本文と違う。ソースの本文は書かない。報告は、そのページ ID をローカル編集と呼ぶ。この差が残るあいだ、新しいソースの本文は入らない。種類と公開状態は維持する。本文が最後の取り込みと一致したままのタイトルだけの差は、ローカル編集ではない。ソースの本文が新しいときは、置き換えの規則がソースのタイトルをまだ書き込める。

##### 空の本文による拒否

取得した本文が空であり、結果の公開状態が public である。報告は、そのページ ID を空の本文による拒否と呼ぶ。この結果はローカル編集とは別である。

##### ページ本文を取得できない

上で定めたページ本文の要求が失敗した。報告は、そのページ ID を取得できないと呼ぶ。この結果は、ローカル編集とも、空の本文による拒否とも別である。

報告には、エントリの本文、最後に取り込んだ本文、CLI トークンを含めない。

## データ要件

### 必要なデータ

- **取り込んだエントリ:** 所有者の書き込みが保存する項目。種類、公開状態、タイトル、本文、不変 ID、正規 URL、bookmark の URL を含む。この機能の作成は公開の page である。後の取り込みは、これらの項目を使って種類、公開状態、bookmark の URL を変えない。
- **Cosense のページ ID:** ソースのページを外部で識別する値。一つのページ ID を持つエントリは、多くて一つである。所有者の手作業の書き込みは、これを消さない。所有者が入力する項目としては出さない。そのエントリがあるあいだ残す。
- **最後に取り込んだ本文:** そのページの最後の成功した取り込みが確定した行テキスト。後のローカル編集を判別するために残す。後の取り込みが確定したときだけ置き換える。公開ページとしては別に出さない。
- **ソースの更新時刻:** 最後の成功した取り込みが確定したときに、Cosense から読んだ更新時刻。エントリの更新時刻ではなく、ソースの時刻として比較する。後の取り込みが確定したときだけ置き換える。
- **走査の位置:** 現在の終わっていない走査で最後に完了した Cosense のページ ID と、その走査が終わったかどうか。終わっていない走査は、これで続きから行う。終わった走査の次の実行は、一覧の先頭から行う。

### 関係

Cosense のページ ID 一つは、多くて一つのエントリに対応する。そのエントリは、最後に取り込んだ本文を一つと、ソースの更新時刻を一つ持つ。走査の位置はプロジェクト一覧の中の位置であり、すべてのエントリの項目ではない。辺はエントリに属し、所有者の書き込みに従う。公開の page は配送対象ではない。

### 個人情報

取り込んだタイトルや本文は、所有者または他の人の名前を含むことがある。作成はページを public で保存するので、そのテキストは誰でも読める。取り込み元のプロジェクトは、既に公開されている。この機能はアカウント情報を集めない。

ページ ID の報告は、CLI を実行する所有者のためのものである。公開の応答ではない。CLI トークンの値は、報告、公開の応答、リポジトリには出さない。

## 外部サービスへの依存

- **Cosense の公開プロジェクト `https://scrapbox.io/yamanoku/`**
  - **関係するユーザーストーリー:** 新しいページを取り込む、一覧の続きと再確認、ローカル編集を残す、ファイルの URL を本文に残す
  - **依存する理由:** ページとプレーンテキストの本文は、このプロジェクトから来る。一覧には本文の行が無い。
  - **契約条件と利用条件:** 取り込み元は、この公開プロジェクトだけである。この機能は、有料の Cosense プランを追加しない。HTTP 429 は、`Retry-After` があるときはそのヘッダに従う。ヘッダの無い 429 と 5xx は、60 秒待って同じ要求を再試行する。アプリ自身は有料プランへ移さない。

- **Cloudflare D1（所有者の書き込みを経由する）**
  - **関係するユーザーストーリー:** 新しいページを取り込む、一覧の続きと再確認
  - **依存する理由:** 保存するページは、エントリと辺の書き込みである。
  - **契約条件と利用条件:** 次のページが残りの無料の書き込み枠に収まらないとき、または枠を使い切って書き込みが拒否されたとき、そのページは完了にせず、実行は 00:00 UTC まで待つ。保存済みの行は残る。アプリ自身は有料プランへ移さない。

## セキュリティ上の考慮事項

取り込みは、所有者の CLI トークンで実行する。トークンを確認できない実行は、何も保存しない。走査も進めない。HTTP 署名は、取り込みを許可しない。ブラウザ認証は、このコマンドの資格ではない。

報告は、所有者へ Cosense のページ ID を列挙する。エントリの本文とトークンの値は含めない。この機能が作るページは公開である。残したローカル編集は、所有者が既に付けた公開状態を維持する。

## 未決事項

ローカル編集のあとで、より新しい Cosense の本文を採る手順は未決である。所有者がその手順を決めるまでは、この機能は Cosense のページ ID を報告する。ローカルの本文と辺は残す。本文の差が残るあいだ、新しいソースの本文は取り込まない。決めるのは所有者である。この決定は、上の作成、再開、置き換えの規則を変えない。

辺の規則が Cosense の画面上のリンク範囲と一致するかは、所有者の書き込みの未決事項のままである。この機能はその規則を使い、変えない。
