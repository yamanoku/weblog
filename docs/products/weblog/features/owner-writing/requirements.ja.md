# 所有者の書き込み

[English](requirements.md)

## このドキュメントについて

所有者は、ブラウザと CLI から同じ規則でエントリを扱う。操作は次のとおりである。

- 作成
- 更新
- 公開
- 削除
- 読み戻し

正規 URL は作成時に一度決まる。タイトルを変えても、正規 URL は残る。本文と、本文から作った辺は、同じ更新で確定する。

親プロダクトは [weblog.yamanoku.net](../../product.ja.md) である。

### スコープ

- 所有者によるエントリの作成、更新、公開、下書きへの変更、削除、一件の取得、一覧
- ブラウザの所有者認証と CLI トークン
- 不変 ID、正規 URL、閲覧用パス、リネーム後の移転
- 下書きを未認証の応答に出さないこと
- 本文から辺を作り、エントリと同じ更新で確定すること
- 最初の HTML のあと、編集画面はブラウザで動く。項目の送信は、CLI と同じ書き込み規則を使う

### スコープ外

- 人間向けフィードの形式、件数、並びの画面、タイトル一覧、空ページの HTML。公開閲覧の機能で決める。下書きの本文をそこへ出さない制約は、この機能が課す。
- ActivityPub のアクター、Follow、署名、活動の送信。この機能は、配送の判断に必要な状態を残す。活動は送らない。
- bookmark の外部 URL を、配送する Note の本文へリンクとして出すこと。URL を本文とは別の項目として保存するところまでを、この機能が行う。
- Cosense からの一括取り込み、再試行、ローカル編集との合流。取り込みがエントリを書くときは、この機能の検証と、エントリと辺の同じ更新境界を通る。取り込みが直接保存する経路は作らない。
- 画像の公開 URL、リンク以外の記法の描画、ORM。
- 複数所有者、登録、同時編集の項目同士の合流。

## ユーザーストーリー

### エントリを作る

所有者として、ブラウザまたは CLI からエントリを作りたい。それによって記事、ミニブログ、ブックマーク、ページを同じホストに置き、正規 URL を一度で固定できる。

**受け入れ条件:**

Scenario: 必須項目が揃っている場合、不変の正規 URL を発行して保存する

- Given: 要求が所有者のブラウザ認証、または有効な CLI トークンで確認できている。同じ不変 ID のエントリは無い。
- When: 所有者が種類、タイトル、本文、公開状態を送る。種類が bookmark のときは外部 URL も送る。
- Then: エントリが一つできる。不変 ID は作成時に一度だけ発行される。正規 URL は `https://weblog.yamanoku.net/e/{id}` である。タイトルを後から変えても、この URL は変わらない。

Scenario: タイトルを必須とする種類でタイトルが空の場合、保存しない

- Given: 要求が所有者として確認できている。
- When: 所有者が種類 article、bookmark、page のいずれかと、空のタイトルで作成を送る。前後の空白だけのタイトルも空とする。
- Then: エントリを作らない。辺も作らない。応答は、タイトルが無いために拒否したと所有者が区別できる。

Scenario: bookmark の外部 URL が無い場合、保存しない

- Given: 要求が所有者として確認できている。
- When: 所有者が種類 bookmark、タイトル、本文を送り、外部 URL を送らない。
- Then: エントリを作らない。辺も作らない。応答は、外部 URL が無いために拒否したと所有者が区別できる。

Scenario: タイトルの無い note の場合、正規 URL だけで公開できるエントリを保存する

- Given: 要求が所有者として確認できている。
- When: 所有者が種類 note、空のタイトル、本文、公開状態を送る。
- Then: エントリを保存する。未認証が辿れる URL は正規 URL だけである。この note は、他の本文からのタイトル参照の解決先にしない。

### エントリを更新する

所有者として、同じエントリの本文、タイトル、種類、公開状態を更新したい。それによって正規 URL を保ったまま内容を差し替え、本文中のリンクを辺として残せる。

**受け入れ条件:**

Scenario: 後から確定した書き込みの場合、その項目でエントリを置き換える

- Given: エントリが一つある。所有者の二つの書き込みが、そのエントリへ順に確定する。
- When: 後の書き込みが種類、タイトル、本文、公開状態、外部 URL を送る。
- Then: その五つの項目は、後の書き込みの値になる。先の書き込みとは項目を合流しない。不変 ID と正規 URL は変わらない。Cosense のページ ID は、この書き込みでは消さない。

Scenario: 検証に失敗した更新の場合、直前の本文と辺を残す

- Given: エントリと、その本文から作った辺が確定している。
- When: 所有者が、タイトル必須の種類へ空のタイトルで更新を送る。
- Then: エントリの本文、タイトル、種類、公開状態、辺は、更新前のままである。

Scenario: 公開で本文が空の場合、保存しない

- Given: 所有者として確認できた要求である。
- When: 所有者が、公開状態 public と空の本文を送る。
- Then: 新規はエントリを作らない。更新は、直前の本文と辺を残す。応答は、認証の失敗とは別である。

Scenario: 下書きで本文が空の場合、空文字を保存する

- Given: 所有者として確認できた要求である。
- When: 所有者が、公開状態 draft と空の本文を送る。
- Then: 本文は空文字で保存される。public から draft への変更も、空文字を保存する。

Scenario: 本文にページ参照がある場合、エントリと辺を同じ更新で確定する

- Given: 公開エントリの現在のタイトルは `Luma AI` である。
- When: 所有者が、別のエントリの本文に、コードブロックの外で `[Luma AI]` と書いて保存する。
- Then: そのエントリの新しい本文と、リンク元の不変 ID、書かれたタイトル `Luma AI`、解決先の不変 ID を持つ辺が、同時に読める。本文だけ、または辺だけが新しい状態は読めない。

Scenario: 外部 URL や装飾の括弧の場合、辺にしない

- Given: 要求が所有者として確認できている。
- When: 所有者が本文に `[https://example.com]`、`[GitHub.icon]`、`[*強調]` を含めて保存する。
- Then: エントリは保存する。これらの括弧からは辺を作らない。行のテキストは残す。

Scenario: タイトルを変えた場合、正規 URL を維持して旧パスを移す

- Given: 公開エントリに閲覧用パスがあり、不変 ID の正規 URL がある。
- When: 所有者が、衝突しない新しいタイトルで更新する。
- Then: 正規 URL は変わらない。旧タイトルは過去タイトルに残る。旧タイトルのパスは、新しい閲覧用パスへ 301 で移る。他のエントリの本文と、そこに書かれた辺のタイトル文字列は変えない。

Scenario: 閲覧用パスが衝突する場合、両方を正規 URL だけで公開する

- Given: タイトル `A B` の公開エントリがあり、閲覧用パスを持つ。
- When: 所有者が、タイトル `A_B` の公開エントリを保存する。
- Then: どちらのエントリにも閲覧用パスを作らない。両方とも正規 URL で読む。`A B` が持っていた旧パスは、そのエントリの正規 URL へ 301 で移る。

### 公開状態を変える

所有者として、下書きと公開を切り替えたい。それによって未完成の本文を公開面から外せ、公開した記事だけを配送の対象にできる。

**受け入れ条件:**

Scenario: 下書きにした場合、未認証の応答から本文を消す

- Given: 所有者が本文を読めるエントリがある。
- When: 所有者が公開状態を draft にして保存する。
- Then: 所有者の取得では本文を返す。未認証の正規 URL は、そのエントリが無いときと同じ応答になる。下書きの本文は、フィード、タイトル一覧、空ページ、配送に出さない。

Scenario: 記事、ミニブログ、ブックマークを公開した場合、配送対象の時刻を記録する

- Given: 要求が所有者として確認できている。エントリの種類は article、note、bookmark のいずれかである。
- When: 所有者が公開状態を public にして保存する。
- Then: 未認証が本文を読める。publishedAt は、この保存で配送対象になった時刻である。既に配送対象だったエントリでは、publishedAt を変えない。

Scenario: ページを公開した場合、本文は公開し配送対象にはしない

- Given: 種類が page のエントリがある。
- When: 所有者が公開状態を public にして保存する。
- Then: 未認証が本文を読める。このエントリは配送対象にしない。publishedAt は付けない。人間向けフィードの対象にもしない。

Scenario: 配送対象でなくした場合、配送済みの印は残す

- Given: 配送対象であり、ActivityPub の機能が配送済みと記録したエントリがある。
- When: 所有者が公開状態を draft にするか、種類を page にして保存する。
- Then: エントリは配送対象でなくなる。不変 ID、正規 URL、配送済みの記録は残る。この機能は Delete 活動を送らない。

### エントリを削除する

所有者として、エントリを削除したい。それによって公開面から本文が消え、一度配送した URL は削除済みだと分かる。

**受け入れ条件:**

Scenario: 配送したことが無いエントリを削除した場合、正規 URL を 404 にする

- Given: エントリがあり、配送済みの記録は無い。要求が所有者として確認できている。
- When: 所有者がそのエントリを削除する。
- Then: 所有者の取得と一覧に、編集できるエントリとしては出ない。正規 URL の公開応答は 404 である。削除前の本文は返さない。

Scenario: 配送したことがあるエントリを削除した場合、正規 URL を 410 にする

- Given: ActivityPub の機能が、そのエントリを配送済みと記録している。要求が所有者として確認できている。
- When: 所有者がそのエントリを削除する。
- Then: 正規 URL の公開応答は 410 である。Activity Streams を求める応答は Tombstone を返す。削除前の本文は返さない。不変 ID は別のエントリへ再利用しない。

Scenario: 資格の無い削除の場合、エントリを残す

- Given: エントリがある。要求が所有者として確認できていない。
- When: その要求が削除を送る。
- Then: 応答は 401 である。エントリ、辺、公開状態は変わらない。

### CLI トークンを発行して書く

所有者として、ブラウザのログインを経由しない CLI トークンで書きたい。それによってプログラムが、所有者と同じ作成、更新、公開、削除、取得、一覧を実行できる。

**受け入れ条件:**

Scenario: ブラウザの所有者セッションで発行した場合、トークンを一度だけ返す

- Given: ブラウザの要求が所有者として確認できている。CLI トークンはまだ無い。
- When: 所有者がトークンの発行を求める。
- Then: 応答にトークンを一度だけ含める。以後の取得や一覧は、そのトークンの値を返さない。保存するのはハッシュだけである。

Scenario: 再発行した場合、直前のトークンを無効にする

- Given: 有効な CLI トークンが一つある。所有者として確認できている要求がある。
- When: 所有者がトークンを再発行する。
- Then: 新しいトークンを一度だけ返す。直前のトークンを付けた書き込みは 401 になり、エントリは変わらない。有効なトークンは一つである。

Scenario: 有効な CLI トークンで作成した場合、ブラウザと同じ結果にする

- Given: 有効な CLI トークンがある。ブラウザのログイン手続きは通っていない。
- When: CLI がそのトークンで、必須項目の揃った作成を送る。
- Then: ブラウザの所有者セッションで同じ項目を送ったときと同じエントリができる。

## 機能要件

### 書き込み

**概要:** ブラウザと CLI は、同じ書き込み規則を使う。一つの書き込みは、種類、タイトル、本文、公開状態を渡す。種類が bookmark のときは外部 URL も渡す。後から確定した書き込みが、これらの項目の新しい状態になる。

**入力:** 所有者として確認できた要求。項目は、種類、タイトル、本文、公開状態、bookmark の外部 URL である。CLI は、作成と更新の本文をファイルから受け取る。作成と更新と公開は、同じ CLI から呼べる。削除と取得と一覧も、同じ CLI から呼べる。受け取る項目は、この節のままである。

**出力:** 確定したエントリ、または拒否の理由。拒否のとき、エントリと辺は変わらない。

#### 適用する条件

##### 項目の置換

作成と更新は、種類、タイトル、本文、公開状態を一緒に渡す。bookmark の更新は外部 URL も渡す。渡した項目は、正規化のあと、そのエントリの現在の値になる。不変 ID、作成時刻、過去タイトル、Cosense のページ ID、配送済みの記録は、項目の置換では消さない。タイトルが正規化後に変わったときだけ、旧タイトルを過去タイトルへ加える。

作成時刻は、作成が確定した時刻である。更新時刻は、その後の書き込みが確定した時刻である。

##### 種類

種類は article、note、bookmark、page の四つである。本文の長さや、本文に URL が含まれるかでは分類しない。四つ以外の種類は拒否し、保存しない。

article はブログ記事である。note はミニブログである。bookmark は外部 URL とコメントである。page は取り込みページと、リンク先に使うページである。所有者は、取り込みを経由しなくても page を作れる。

##### タイトル

比較の前に、前後の空白を除き、連続する空白を一つにまとめる。大文字と小文字は区別する。正規化後の現在のタイトルは、エントリにつき一つである。

article、bookmark、page はタイトルを必須にする。note は空のタイトルで保存できる。空のタイトルの note は、タイトル参照の解決先にしない。

##### 外部 URL

bookmark の外部 URL は、本文とは別の必須項目である。本文は、所有者が送ったテキストのまま保存し、この機能では URL を本文へ挿入しない。article、note、page では外部 URL を必須にしない。これらの種類の書き込みに URL が無ければ、外部 URL は空になる。

##### 公開状態

公開状態は draft と public の二つである。それ以外は拒否し、保存しない。

配送対象は、種類が article、note、bookmark のいずれかであり、かつ public であるエントリである。page は public でも配送対象にしない。draft は配送対象にしない。

publishedAt は、エントリが配送対象になった時刻である。配送対象でないエントリには付けない。既に配送対象であるエントリの更新では変えない。配送対象でなくしたあと、再び配送対象にしたときは、その時刻へ更新する。

##### 閲覧用パス

正規 URL は `https://weblog.yamanoku.net/e/{id}` である。ActivityPub のオブジェクト ID と、人間向けフィードの項目 ID も、この URL を使う。フィードの中身と活動の送信は、それぞれの機能が決める。

閲覧用パスは `/{タイトル}` である。タイトル中の空白は `_` に変えてから、百分率符号化する。タイトルの無い note には閲覧用パスを作らない。

タイトル自体に `_` があるページと、空白を `_` にしたページが同じパスになる場合、そのパスはどちらの閲覧用パスにもしない。衝突したページの公開 URL は正規 URL だけである。衝突で閲覧用パスをやめた旧パスは、そのエントリの正規 URL へ 301 で移す。

リネーム後、旧タイトルのパスは、現在の閲覧用パスへ 301 で移す。現在の閲覧用パスが無いときは、正規 URL へ 301 で移す。

##### 本文と辺

エントリと、その本文から作った辺は、同じ更新で確定する。片方だけが新しい状態を読ませない。保存できないときは、どちらも更新前のままにする。

空の本文は、空文字である。空白だけの本文は空にしない。

public で本文が空の書き込みは、保存しない。作成はエントリを作らない。更新は、直前の本文と辺を残す。draft から public への変更も、本文が空なら保存しない。この拒否は、認証の失敗とは別である。

draft で本文が空の書き込みは、空文字を保存する。public から draft への変更も、本文が空なら空文字を保存する。

辺は、リンク元の不変 ID、本文に書かれたタイトル、解決先の不変 ID を持つ。解決先が無い辺も残す。抽出結果の構文木は保存しない。保存するのは、行のテキストと、次の規則で作った辺である。

他のエントリの本文は、この書き込みでは変えない。辺に保存したタイトル文字列を変えるのは、その辺のリンク元の本文を、所有者が書き換えたときだけである。リネームだけでは、他のエントリの辺のタイトル文字列を変えない。

リンクの抽出は、行のテキストに対して次の規則で行う。

- `code:` または `table:` で始まる行と、その直後に続く、行頭が空白の行は、辺の対象外にする。
- 対象外の行の外では、`#` の直後から、空白、`[`、`]`、行末のいずれかの手前までを、タグのタイトルにする。
- タグのタイトルが空なら辺にしない。`#2016 年にリメイクした` の辺のタイトルは `2016` だけである。
- `[` と対応する `]` で囲み、改行を含まない中身だけを、ページの辺の候補にする。
- 中身が `http://` または `https://` で始まる場合は、外部 URL であり、辺にしない。
- 空白で区切った一部が `http://` または `https://` で始まる場合も、辺にしない。
- 末尾が `.icon` の中身は、アイコンであり、辺にしない。
- 先頭が `*`、`**`、`***`、`-` の中身は、装飾であり、辺にしない。
- それ以外の中身は、タイトルと同じ正規化をしたページタイトルとして辺にする。

未認証の解決先は、現在のタイトルが一致する public のエントリだけである。そのタイトルを現在のタイトルとして使うエントリが無く、過去タイトルが一致する public のエントリがあるときは、そのエントリを解決先にする。draft は、所有者の表示でだけ解決する。一致する公開エントリが無い辺は残す。閲覧だけではエントリを作らない。

##### 取得と一覧

所有者の一件取得と一覧は、draft と public、四つの種類を含む。未認証の応答は draft の本文を含まない。未認証の一覧、フィード、タイトル一覧の形式は、公開閲覧の機能が決める。

##### 無料枠を超えた保存

保存が無料枠を超えて確定できないとき、エントリと辺は更新前のままにする。有料プランへは移さない。応答は、保存できなかったと所有者が区別できる。認証の失敗とは区別できる。

#### 例外ケースでの振る舞い

##### 認証できない要求

所有者として確認できない書き込み、削除、トークンの発行は、401 を返し、エントリと辺を変えない。入力が不正な拒否は、401 にしない。401 以外の状態コードは、404、410、301 のいずれとも衝突しない範囲で Design が選ぶ。

##### 削除済みの正規 URL

配送済みの記録が無い削除済み ID は、404 を返す。配送済みの記録がある削除済み ID は、410 を返す。Activity Streams を求める 410 の応答は Tombstone を返す。どちらの応答も、削除前の本文を含まない。タイトルのパスは、公開エントリの現在のタイトルとして解決しない。削除した本文を、空ページへ出さない。

### CLI トークン

**概要:** 所有者は CLI トークンを発行し、再発行する。CLI はブラウザのログイン手続きを通らない。

**入力:** 所有者として確認できた発行の要求。書き込みに付けるときは、発行済みのトークン。

**出力:** 発行時のトークン。それ以外の応答にはトークンの値を含めない。

#### 適用する条件

##### 最初の発行と再発行

最初のトークンは、ブラウザの所有者セッションから発行する。発行前の CLI には、トークンが無いためである。再発行は、ブラウザの所有者セッション、または有効な CLI トークンからできる。再発行は直前のトークンを無効にする。有効なトークンは一つである。

保存するのはハッシュだけである。トークンの値は、発行した応答で一度だけ返す。

#### 例外ケースでの振る舞い

##### 無効なトークン

無効なトークン、または再発行で無効になったトークンを付けた要求は、401 を返す。エントリと辺は変えない。

##### ブラウザの認証サービスが確認できない

ブラウザの認証サービスが所有者を確認できないとき、ブラウザからの書き込みと発行は 401 にする。既に発行した CLI トークンの確認は、そのサービスを使わない。

## データ要件

### 必要なデータ

- **エントリ:** 不変 ID と種類を持つ。正規化後の現在のタイトルと過去タイトルも持つ。本文の行テキストと公開状態も持つ。作成時刻と更新時刻も持つ。bookmark の外部 URL、publishedAt、Cosense のページ ID も持つ。削除後、未配送のエントリは公開の取得対象から外す。配送済みの削除済み ID は、本文なしの 410 として残す。
- **辺:** リンク元の不変 ID、本文に書かれたタイトル、解決先の不変 ID。リンク元の本文を保存するのと同じ更新で置き換える。解決先が無くても残す。
- **CLI トークンのハッシュ:** 所有者が発行したトークンの確認に使う。値そのものは保持しない。再発行で直前のハッシュは無効になる。
- **配送済みの記録:** 一度でも配送したことを示す。ActivityPub の機能が記録する。この機能は、公開状態や種類の変更と、未配送の削除では、その記録を消さない。配送済み ID の削除後も、410 を返すために残す。

### データ間の関係

エントリは不変 ID を一つ持つ。現在のタイトルは、空の note を除き一つ持つ。過去タイトルは、そのエントリの古い現在のタイトルである。辺は一つのリンク元エントリに属し、本文に書かれたタイトルで、零または一つの解決先を指す。bookmark の外部 URL は、そのエントリの本文とは別の項目である。CLI トークンのハッシュは、所有者の書き込み資格であり、エントリには属さない。配送済みの記録は、一つの不変 ID に対応する。

### 個人情報

所有者 yamanoku の本人確認に、ブラウザ認証の識別子と CLI トークンを使う。目的は、書き込みを所有者に限ることである。識別子とトークンの値は、公開応答へ出さない。

本文、タイトル、bookmark の URL は、所有者や第三者の名前を含むことがある。public のエントリは未認証で読める。draft の本文は所有者だけが読める。この機能は、公開状態の選択以外に、本文に書かれた第三者の同意を集める手続きを持たない。

トークンのハッシュは、再発行で無効にするまで保持する。削除済みで配送済みの ID は、リモートが参照する URL として、本文なしで残す。保持期間の期限は設けない。

## 依存する外部サービス

- **Cloudflare Access（Zero Trust の Free プラン）**
  - **関連するユーザーストーリー:** エントリを作る、CLI トークンを発行して書く
  - **依存する理由:** ブラウザの編集画面で、所有者一人を確認する。登録機能は持たない。最初の CLI トークンは、この確認ができたセッションから発行する。
  - **契約・利用上の判断:** Free プランを使う。席は 50 まで追加料金が無く、使うのは所有者一人である。有料の追加機能は有効にしない。有料プランへは自動で移さない。このサービスを外すときは、下の未決事項に書いた三つの要件を決める。CLI トークンの規則は変えない。ドメイン名の登録維持費は、この依存の費用に含めない。2026-10-17 の Cloudflare Community は、Free プランが席数で頭打ちになると説明している。Log Explorer などの有料追加は、明示的なアップグレードが無い限り課金されない。支払い情報の入力を求められても、Free を選んだ組織は課金されない。その手順の更新日は 2026-10-12 である。

## セキュリティ上の留意事項

ブラウザの所有者認証、CLI トークン、サーバ間の HTTP 署名は、別の資格である。HTTP 署名では書き込みを認めない。CLI トークンでは、inbox の送信元を認めない。

書き込み、削除、トークンの発行は、要求ごとに所有者かどうかを確認する。ブラウザの編集画面を認証サービスの背後に置くことだけでは、書き込みを認めない。

未認証の応答は、draft の本文を返さない。draft が存在するかどうかは、未認証の応答から区別できない。

CLI トークンの値と、ブラウザ認証の検証に使う秘密は、公開応答とリポジトリへ置かない。保存してよいのはトークンのハッシュである。

## 未決事項

Cosense の画面上のリンク範囲と、この機能の抽出規則が違ったときの扱いは未決である。決まるまでは、上の抽出規則で辺を作る。取得した本文と画面を所有者が比べ、違いがあると判断したときに、所有者が規則を変える。違いが無いと決まったわけではない。

Access を外したあとのブラウザ認証の方式は未決である。パスキーは候補として挙がっているだけで、採用とは決めていない。初版のブラウザ側は Access と決めた。CLI トークンの規則は変えない。置き換え先を決めるのは所有者である。それまでは、上の契約の文を変えない。

外すと決めるとき、所有者は次の三つを要件に書く。

- 一つ目は、ブラウザの要求を所有者だと確認する手段である。パスキーを使うなら、そのときに採用と書く。
- 二つ目は、最初の CLI トークンを出すセッションの作り方である。本人確認が済んだブラウザセッションから出すことは決まっている。新しい方式が、そのセッションをどう作るかを書く。
- 三つ目は、ログインの境界を変えるかどうかである。公開の閲覧、人間向けフィード、WebFinger は、ログインの外にある。inbox と CLI の `/entries` も、ログインの外にある。維持するなら、そのままと書く。変えるなら、変える経路を書く。
