# 公開閲覧

[English](requirements.md)

## このドキュメントについて

未認証の閲覧者は、ログインせずに公開エントリを読む。人間向けフィード、タイトル一覧、空ページ、Gyazo の画像も読む。本文の正本はプレーンテキストのままである。表示用の HTML は、その本文から作る。

親プロダクトは [weblog.yamanoku.net](../../product.ja.md) である。書き込みの規則は [所有者の書き込み](../owner-writing/requirements.ja.md) にある。

### スコープ

- 未認証の `GET /`、`GET /{タイトル}`、`GET /e/{id}` の HTML
- 人間向けフィードとタイトル一覧
- 公開エントリが無く、公開の内向き辺があるタイトルの空ページ
- Gyazo 画像の公開 URL と、そのバイト列
- 公開 HTML のリンク
- 最初の HTML のあと、このホストの別の公開 HTML ページへのリンクは、ブラウザがページを更新する。文書全体は置き換えない

### スコープ外

- 所有者による作成、更新、削除、ブラウザ認証、CLI トークン
- ActivityPub のアクター、Follow、署名、活動の送信、生きているエントリの Activity Streams
- WebFinger、outbox、フォロワー、inbox
- Cosense からの一括取り込み
- リンク以外の Cosense 記法を HTML にする順序。この機能ではソースのテキストのまま見せる
- ORM
- 所有者の書き込み API と、所有者向け一覧の 50 件

## ユーザーストーリー

### 公開 HTML ページのあいだを移動する

未認証の閲覧者として、このホストの次の公開 HTML ページをブラウザで開きたい。それによって、文書全体は置き換わらない。

**受け入れ条件:**

Scenario: このホストの別の公開 HTML ページへのリンクをたどる場合、ブラウザがページを更新する

- Given: 閲覧者は、公開ページの最初の HTML を持っている。
- When: 閲覧者が、このホストの別の公開 HTML ページへのリンクをたどる。
- Then: ブラウザはそのページを更新する。文書全体は置き換えない。どちらの URL への直接の要求も、これまでどおり 200 の HTML である。フィードと画像のバイト列は、この移動ではない。

### 公開エントリを読む

未認証の閲覧者として、ログインせずに公開エントリを開きたい。それによって、このホストの記事、ミニブログ、ブックマーク、ページを読める。

**受け入れ条件:**

Scenario: 公開エントリに閲覧用パスがある場合、そのパスでエントリを返す

- Given: 公開エントリに閲覧用パスと本文がある。
- When: 未認証のクライアントが、その閲覧用パスを要求する。
- Then: 応答は 200 の HTML である。本文を含む。本文中のページの辺はリンクである。行のテキストは残る。ログインは要らない。

Scenario: 正規 URL を開いた場合、同じ公開エントリを返す

- Given: 公開エントリの正規 URL は `https://weblog.yamanoku.net/e/{id}` である。
- When: 未認証のクライアントが、Activity Streams を求めずにその URL を要求する。
- Then: 応答は、そのエントリの 200 の HTML である。正規 URL は、作成時のままである。

### note につながった投稿を読む

未認証の閲覧者として、note の正規 URL で、その note と所有者の返信を古い順にまとめて読みたい。それによって、つながった投稿を一つのページで読める。

**受け入れ条件:**

Scenario: 返信が無い note の場合、正規 URL はその note を出す

- Given: 公開の note は、他の note への返信ではない。そのスレッドに返信する公開 note は無い。公開の article が一つある。
- When: 未認証のクライアントが、Activity Streams を求めずに、その note の正規 URL を要求する。
- Then: 応答は 200 の HTML であり、その note の本文を含む。article の本文は含めない。返信欄は含めない。

Scenario: スレッドのどの note を開いても、同じ投稿が古い順に出る

- Given: 公開の note A は、他の note への返信ではない。公開の note B は A への返信である。公開の note C は B への返信である。公開の article が一つある。
- When: 未認証のクライアントが、Activity Streams を求めずに、A、B、C の正規 URL を要求する。
- Then: 各応答は 200 の HTML である。各応答は A、B、C の本文を含む。順序は作成時刻の古い順で、同じ時刻は不変 ID の昇順である。B は A への返信であると示す。C は B への返信であると示す。A は返信先を示さない。article の本文は無い。B と C は、GET `/` と note のフィードに無い。

Scenario: スレッドの一つの note を削除した場合、残った note は同じスレッドに残る

- Given: 公開の note A は、他の note への返信ではない。公開の note B は A への返信である。公開の note C は B への返信である。B は削除され、配送済みの記録は無い。
- When: 未認証のクライアントが、Activity Streams を求めずに、C の正規 URL を要求する。
- Then: 応答は 200 の HTML である。A と C の本文を含む。B の本文は含めない。C は返信先を示さない。B の正規 URL は 404 である。

Scenario: 最初の note を削除した場合、残った返信は自分の正規 URL に残る

- Given: 公開の note A は、他の note への返信ではない。公開の note B は A への返信である。A は削除され、配送済みの記録は無い。
- When: 未認証のクライアントが、Activity Streams を求めずに、B の正規 URL を要求する。
- Then: 応答は 200 の HTML であり、B の本文を含む。A の本文は含めない。B は返信先を示さない。A の正規 URL は 404 である。

Scenario: note でないエントリの場合、note のスレッドを並べない

- Given: 公開の article がある。公開の note が、別の公開 note へ返信している。
- When: 未認証のクライアントが、Activity Streams を求めずに、その article の正規 URL を要求する。
- Then: 応答は、その article の 200 の HTML である。note の本文は含めない。

Scenario: エントリが draft の場合、無いエントリと同じ応答にする

- Given: エントリは draft である。閲覧用パスを持っていてもよい。
- When: 未認証のクライアントが、正規 URL または閲覧用パスを要求する。
- Then: 応答は、無いエントリと同じである。draft の本文は含めない。draft であるとは出さない。

Scenario: 配送済みのエントリを削除した場合、HTML に削除前の本文を含めない

- Given: エントリは配送されたあと削除されている。410 の定義は所有者の書き込みにある。
- When: 未認証のクライアントが、Activity Streams を求めずに正規 URL を要求する。
- Then: 応答は 410 である。削除前の本文は含めない。

Scenario: 公開ブックマークの場合、HTML に外部 URL を含める

- Given: 公開の bookmark に外部 URL がある。本文が他の URL に触れていてもよい。
- When: 未認証のクライアントが、そのエントリを要求する。
- Then: HTML は、その外部 URL を外部リンクとして含む。保存された本文は変えない。

Scenario: 公開ブックマークを一覧に出す場合、タイトルは外部 URL を開く

- Given: 公開の bookmark に、`http://` または `https://` で始まる外部 URL がある。閲覧用パスもある。
- When: 未認証のクライアントが `GET /` または `GET /pages` を開く。
- Then: タイトルのリンクは、その外部 URL である。閲覧用パスにはしない。正規 URL にもしない。正規 URL を直接要求したとき、応答はそのエントリの HTML である。

### 人間向けフィードを読む

未認証の閲覧者として、配送対象のフィードを読みたい。それによって、タイトル一覧をフィードと取り違えずに、新しい記事、ミニブログ、ブックマークを追える。

**受け入れ条件:**

Scenario: 配送対象がある場合、最初のページは 10 件である

- Given: 配送対象が 10 件より多い。公開の page があり、その page は配送対象ではない。
- When: 未認証のクライアントが `GET /`、`GET /feed.xml`、`GET /feed.json` のいずれかを要求する。
- Then: 応答は配送対象を 10 件出す。順序は `publishedAt` の新しい順である。同じ時刻は不変 ID の降順である。公開の page は含めない。各項目は本文を含む。項目の ID は正規 URL である。

Scenario: 配送対象が 10 件より多い場合、次のページの URL を返す

- Given: 配送対象が 11 件ある。
- When: 未認証のクライアントが、フィードの最初のページを要求する。
- Then: 応答は次のページの URL を含む。そのページは残りの 1 件を含み、さらに次の URL は含めない。

Scenario: 配送対象が無い場合、空の成功応答にする

- Given: 配送対象は無い。公開の page はあってもよい。
- When: 未認証のクライアントが `GET /` を要求する。
- Then: 応答は 200 である。一覧は空である。404 にはしない。

Scenario: 種類を指定した場合、その種類だけの Atom を返す

- Given: 配送対象の article、note、bookmark がある。
- When: 未認証のクライアントが `GET /feed/articles.xml`、`GET /feed/notes.xml`、`GET /feed/bookmarks.xml` のいずれかを要求する。
- Then: 各フィードはその種類だけを含む。件数と順序は `GET /feed.xml` と同じである。

### タイトルを辿る

未認証の閲覧者として、タイトルを辿り、まだエントリの無いタイトルも開きたい。それによって公開ページがリンクのグラフになり、タイトル一覧はフィードと別のままになる。

**受け入れ条件:**

Scenario: 公開タイトルがある場合、一覧は 10 件である

- Given: タイトルを持つ公開エントリが 10 件より多い。その中に公開の page がある。タイトルが空の配送対象 note がある。
- When: 未認証のクライアントが `GET /pages` を要求する。
- Then: 応答はタイトルを 10 件出し、本文は出さない。順序は更新時刻の新しい順である。同じ時刻は不変 ID の降順である。公開の page は含める。空のタイトルは出さない。次のページの URL を含む。各項目は、そのエントリの正規 URL `/e/{id}` へのパーマリンクを持つ。表示文言は `パーマリンク` である。

Scenario: 公開エントリが無く公開の内向き辺がある場合、空ページを返す

- Given: そのタイトルの公開エントリは無い。公開エントリから、そのタイトルへの辺がある。同じタイトルの draft があってもよい。
- When: 未認証のクライアントが、そのタイトルのパスを要求する。
- Then: 応答は 200 である。タイトルと、公開のリンク元の現在のタイトルを含む。draft の本文は含めない。エントリは作らない。

Scenario: 公開エントリも公開の内向き辺も無い場合、404 にする

- Given: そのタイトルの公開エントリは無い。公開の内向き辺も無い。
- When: 未認証のクライアントが、そのタイトルのパスを要求する。
- Then: 応答は 404 である。draft の本文は含めない。エントリは作らない。

### Gyazo の画像を読む

未認証の閲覧者として、公開 HTML からこのホストの Gyazo 画像を読みたい。それによって、保存された本文を変えずに、既存のアーカイブからバイト列を取得できる。

**受け入れ条件:**

Scenario: 索引に image id と拡張子がある場合、バイト列を返す

- Given: その image id と拡張子のオブジェクトキーが索引に一つある。バケットにはそのオブジェクトが既にある。
- When: 未認証のクライアントが `GET /gyazo/{imageId}.{拡張子}` を要求する。
- Then: 応答はそのオブジェクトのバイト列である。バケットの全件は列挙しない。保存された本文は、元の Gyazo URL のままである。この応答は Workers の要求 1 回に数える。

Scenario: 索引にそのオブジェクトが無い場合、404 にする

- Given: その image id と拡張子のオブジェクトキーは索引に無い。
- When: 未認証のクライアントが、その画像 URL を要求する。
- Then: 応答は 404 である。画像のバイト列は含めない。バケットの全件は列挙しない。

Scenario: 本文中の URL からオブジェクトが一つに決まる場合、HTML はこのホストを指す

- Given: 公開の本文に `i.gyazo.com` または `gyazo.com` の URL がある。索引から、その image id の拡張子を一つ選べる。
- When: 未認証のクライアントが、そのエントリの HTML を要求する。
- Then: HTML は `https://weblog.yamanoku.net/gyazo/{imageId}.{拡張子}` を参照する。保存された本文は、元の URL を含んだままである。

Scenario: 本文中の URL からオブジェクトが一つに決まらない場合、元の URL を残す

- Given: 公開の本文に、拡張子の無い Gyazo URL がある。その image id のオブジェクトキーは複数ある。
- When: 未認証のクライアントが、そのエントリの HTML を要求する。
- Then: HTML はその元の URL を残す。オブジェクトの一つを選ばない。

## 機能要件

### 公開エントリを見せる

**概要:** 未認証のクライアントは、公開エントリを HTML で読む。ログインは要らない。

**入力:** Activity Streams を求めない `GET /{タイトル}` または `GET /e/{id}`。

**出力:** 公開エントリの HTML、空ページ、移転、404、410 のいずれか。

#### 適用する条件

##### どのエントリを公開として扱うか

公開エントリの公開状態は public である。これらの応答に draft の本文は出さない。未認証のクライアントにとって、draft は無いエントリと同じである。閲覧だけではエントリを作らない。

種類は article、note、bookmark、page である。公開の page は、その URL で読める。配送対象、フィードへ載せる条件、`publishedAt` は [所有者の書き込み](../owner-writing/requirements.ja.md) が定義する。この機能は活動を送らない。

正規 URL は `https://weblog.yamanoku.net/e/{id}` である。タイトルを変えても、この URL は変えない。生きているエントリの Activity Streams は、ActivityPub の機能が決める。この機能は、Activity Streams を求めない要求へ HTML を返す。

削除済み ID の 404 と 410 は、所有者の書き込みに従う。配送済みの削除済み ID は 410 であり、HTML に削除前の本文は含めない。未配送の削除済み ID は 404 である。どちらの応答も、削除前の本文を含めない。

##### 閲覧用パスと移転

閲覧用パスは、所有者の書き込みにあるタイトル規則のあとの `/{タイトル}` である。空白は `_` にしてから百分率符号化する。タイトルが空の note に閲覧用パスは無く、公開 URL は正規 URL だけである。この note は、タイトル参照の解決先にしない。

空白を `_` にしたあとでパスを共有するタイトルには、閲覧用パスを作らない。両方とも正規 URL だけで公開する。比較キーが `gyazo` のタイトルにも、閲覧用パスを作らない。

公開エントリの旧パスは、現在の閲覧用パスへ 301 で移す。閲覧用パスが無いときは、正規 URL へ移す。未認証のクライアントを draft へは移さない。その要求は、無いタイトルとして扱う。

##### 本文の HTML

保存された本文はプレーンテキストのままである。公開 HTML は、その文字列を置き換えない。

article の公開 HTML は、保存された本文を Markdown として描く。空行で区切った段落、`#` から `######` の直後に空白がある見出し、`-` または `*` で始まる順序なしリストを HTML にする。`*` と `**` の強調、バッククォートのインラインコード、フェンスのコード、`[表示](URL)` のリンクも HTML にする。リンクの URL は `http`、`https`、またはこのホストのパスだけである。本文中の生の HTML はエスケープし、実行しない。

article 以外の公開 HTML は、保存された行を残す。ページの辺は、解決先の閲覧用パスへのリンクにする。公開の解決先に閲覧用パスが無いときは、正規 URL を使う。公開エントリの無いタイトルへのリンクは残し、空ページを開けるようにする。外部 URL は外部リンクにする。

bookmark の外部 URL は、外部リンクとして見せる。この URL を、保存された本文へは挿入しない。

アイコン、表、数式、Cosense の装飾は、ソースのテキストのまま見せる。それらを HTML にする順序は、その描画の Requirements を書くときに所有者が決める。

`i.gyazo.com` と `gyazo.com` の URL は、下の画像の規則に従う。`scrapbox.io/files` の URL は、元の文字列のまま残す。この機能では、そのファイルを複製しない。

##### note のスレッド

公開 note の正規 URL は、そのスレッドにある公開 note をすべて並べる。順序は作成時刻の古い順で、同じ時刻は不変 ID の昇順である。最初の note は返信先を示さない。後の note は、返信先がまだスレッドにあれば、その note を示す。返信先が無いときも、後の note はスレッドに残り、返信先は示さない。残っているどの note を開いても、同じ一覧が返る。削除済み ID は所有者の書き込みに従い、削除前の本文を返さない。article、bookmark、page は、これまでどおり一件である。それらのページは note のスレッドを並べない。所有者として確認できていない要求は、返信欄を含めない。返信欄の定義は、所有者の書き込みにある。

##### 空ページ

要求されたタイトルの公開エントリが無く、公開エントリからそのタイトルへの辺があるとき、応答は 200 である。ページはタイトルと、それらの公開リンク元の現在のタイトルを示す。リンク元は、閲覧用パスへリンクする。閲覧用パスが無いときは正規 URL へリンクする。draft の本文は出さない。draft があるとは出さない。

そのタイトルの公開エントリが無く、公開の内向き辺も無いときは、応答は 404 である。

### フィードとタイトルを一覧する

**概要:** 人間向けフィードは配送対象を並べる。タイトル一覧は公開タイトルを並べる。どちらも 1 ページ 10 件である。

**入力:** 次の経路。続きのページは、直前の応答が示した次の URL を使う。

- `GET /`
- `GET /feed.xml`
- `GET /feed.json`
- `GET /feed/articles.xml`
- `GET /feed/notes.xml`
- `GET /feed/bookmarks.xml`
- `GET /pages`

**出力:** 10 件のページ。最後のページは 10 件未満でもよい。続きがあるとき、応答は次のページの URL を含む。

#### 適用する条件

##### フィード

`GET /` は HTML である。`GET /feed.xml` は Atom である。`GET /feed.json` は JSON Feed である。三つは同じ配送対象を並べる。必須の形式は Atom である。JSON Feed は、同じ項目の追加の表現である。

`GET /feed/articles.xml`、`GET /feed/notes.xml`、`GET /feed/bookmarks.xml` は、その種類だけの Atom である。種類別の JSON Feed は無い。

フィードに載せるのは配送対象だけである。順序は `publishedAt` の新しい順である。`publishedAt` が同じときは、不変 ID の降順で分ける。page は含めない。他の note への返信である note は配送対象ではないので、GET `/` とこれらのフィードには出さない。取り込んだ page は、所有者が種類を変えるまでフィードに載せない。各項目は本文を含み、項目の ID に正規 URL を使う。外部 URL が `http://` または `https://` で始まる bookmark では、エントリへのリンクはその URL である。それ以外のエントリでは、閲覧用パスがあればそれを使う。無ければ正規 URL を使う。

所有者向け API の 50 件は、別の一覧である。この 10 件とは件数を共有しない。

##### タイトル一覧

`GET /pages` は、公開エントリの全種類のタイトルを並べる。順序は更新時刻の新しい順である。更新時刻が同じときは、不変 ID の降順で分ける。各項目は、タイトルとパーマリンクを出す。本文は出さない。公開の page は含める。タイトルが空のエントリは出さない。この一覧はリンクグラフの入口である。Weblog のフィードではない。bookmark のタイトルは、外部 URL が `http://` または `https://` で始まるとき、その URL へリンクする。それ以外のタイトルは、閲覧用パスへリンクする。閲覧用パスが無いときは、正規 URL へリンクする。パーマリンクは、そのエントリの正規 URL `/e/{id}` を開く。表示文言は `パーマリンク` である。

##### 10 件のページ

これらの応答は 10 件を返す。最後のページはそれより少なくてよい。項目が無いときは 200 であり、一覧は空である。続きがあるとき、応答は次のページの URL を含む。最後のページは、その URL を出さない。ページの列は、順序どおりの一覧を分割する。同じ項目を繰り返さず、項目を飛ばさない。次のページの URL の形は Design が選ぶ。

### Gyazo の画像を返す

**概要:** オブジェクトを一つに選べる Gyazo 画像について、公開 HTML はこのホストを参照する。バイト列は既存のアーカイブから読む。

**入力:** バイト列は `GET /gyazo/{imageId}.{拡張子}`。Gyazo URL を含む本文の、エントリ HTML。

**出力:** 画像のバイト列、404、またはこのホストを参照するか元の URL を残す HTML。

#### 適用する条件

##### バイト列

画像の URL は `https://weblog.yamanoku.net/gyazo/{imageId}.{拡張子}` である。ホストは索引からオブジェクトキーを引き、そのオブジェクトのバイト列を返す。索引は image id から、一つか複数のオブジェクトキーを引く。キーは展開ディレクトリ名を含む。要求の処理中に、バケットの全件は列挙しない。Gyazo のバイト列はアップロードしない。保存された本文は、元の URL 文字列のままである。

索引に無い image id と拡張子の要求は 404 であり、バイト列を含めない。この画像パスでない要求は、アーカイブのバイト列を返さず、バケットの全件も列挙しない。

画像の応答は、Workers の 1 日 10 万要求へ 1 回として数える。

##### HTML が使う URL

書いた URL の末尾の拡張子を、その image id の索引が持つとき、HTML はその拡張子でこのホストを参照する。書いた URL に拡張子が無く、索引のキーが一つなら、HTML はそのキーの拡張子を使う。書いた URL に拡張子が無く、索引のキーが複数なら、HTML は元の URL を残し、オブジェクトを選ばない。索引にキーが無いときも、HTML は元の URL を残す。

この書き換えの対象は、`i.gyazo.com` と `gyazo.com` である。

#### 例外ケースでの振る舞い

##### 無料枠を使い切ったとき

読み取りが無料枠の中で実行できないとき、応答は 404、410、301 のいずれにもしない。閲覧者は、無いエントリとも、削除済みのエントリとも区別できる。アプリは有料プランへ移らない。応答は、閲覧者に有料プランの購入を求めない。状態コードは、この範囲で Design が選ぶ。実行できない処理は、00:00 UTC まで待つか、その要求では失敗する。

## データ要件

### 必要なデータ

- **公開エントリ:** 不変 ID、種類、現在のタイトル、本文、公開状態、bookmark の URL、`publishedAt`、更新時刻、正規 URL、閲覧用パス。タイトルが空のエントリと、閲覧用パスの無いエントリは、正規 URL で読める。
- **辺:** リンク元の ID、本文に書かれたタイトル、公開の解決先があるときの解決先 ID。閲覧は、エントリと一緒に保存済みの辺を使う。この機能は、エントリを作らない。辺も作らない。
- **過去タイトルと移転:** 公開の旧パスを、現在の閲覧用パスまたは正規 URL へ移すために使う。未認証のクライアントの移転先に、draft はしない。
- **削除の記録:** 削除済み ID が配送済みかどうか。HTML が本文なしで 404 または 410 を返すために使う。記録の定義は所有者の書き込みにある。
- **Gyazo の索引:** image id、拡張子、展開ディレクトリ名を含むオブジェクトキー。索引の置き場所は、決めたとおり D1 である。一つの image id が複数のキーを持ってよい。
- **2026-11-01 のローカル展開:** 26.3 GiB だった。同じ image id は、一つのディレクトリだけにあった。複数の拡張子を持つ image id は 243 だった。ファイルの無い metadata は 2 件だった。請求上の使用量は、この測定に含めない。

### 関係

フィードの項目とタイトル一覧の項目は、公開エントリの一つを指す。空ページは、そのタイトルを辺に持つ公開エントリを指す。画像の URL は、オブジェクトキーの一つを指す。

### 個人情報

公開された本文、タイトル、bookmark の URL は、所有者や他の人の名前を含むことがある。それらの公開エントリは、誰でも読める。これらの応答に draft の本文は無い。この機能は、アカウントの情報を集めない。公開画像 URL で返すバイト列は、誰でも取得できる。公開するかどうかは、所有者の公開状態の選択のままである。この機能は、別の同意の手続きを足さない。

## 外部サービス依存

- **Cloudflare Workers Free**
  - **関連するユーザーストーリー:** 公開エントリを読む、人間向けフィードを読む、タイトルを辿る、Gyazo の画像を読む
  - **依存する理由:** 公開ホストは、これらの読み取りを Worker で返す。Gyazo 画像の応答は、要求 1 回に数える。
  - **契約・利用上の判断:** 無料枠は 1 日 10 万要求である。枠のあとは、その要求を失敗させるか、00:00 UTC まで待つ。アプリ自身は有料プランへ移らない。

- **Cloudflare R2 のバケット `gyazo-archives`**
  - **関連するユーザーストーリー:** Gyazo の画像を読む
  - **依存する理由:** 画像のバイト列は、このバケットに既にある。この機能はそれを読み、再びアップロードしない。
  - **契約・利用上の判断:** この既存アーカイブの保存量のうち、月 10 GB を超える分はゼロ円の対象外である。バイト列の複製は作らない。読み取りは Class B である。Class A の無料枠は、月 100 万回である。Class B の無料枠は、月 1000 万回である。保存の無料枠は、月 10 GB である。出典は 2026-10-30 更新の [R2 の料金](https://developers.cloudflare.com/r2/pricing/) である。

- **Cloudflare D1**
  - **関連するユーザーストーリー:** 公開エントリを読む、人間向けフィードを読む、タイトルを辿る、Gyazo の画像を読む
  - **依存する理由:** 公開エントリはエントリの保存先から読む。Gyazo の索引は、同じ D1 にある。
  - **契約・利用上の判断:** 無料枠は、[プロダクトの D1 の枠](../../product.ja.md) である。読み取りを実行できないときは、00:00 UTC まで失敗する。失敗は、無いエントリと区別できる。アプリ自身は有料プランへ移らない。

## セキュリティ上の留意事項

これらの経路は、ログインなしで届く。ホスト全体を、所有者のブラウザログインの背後には置かない。編集画面を所有者に限る規則は、所有者の書き込みにある。

未認証の応答は、draft の本文を含めない。draft があるかどうかも出さない。削除前の本文は返さない。保存された本文はプレーンテキストである。公開 HTML は、その本文を HTML として実行しない。この機能が足すリンクは、上で述べたリンクだけである。

画像の経路は、一つのオブジェクトのバイト列を返す。バケットの全件は列挙しない。

## 未決事項

この機能の Design を止める未決は無い。

article の Markdown は、上の本文の HTML のとおり描く。アイコン、表、数式、Cosense の装飾を HTML にする順序は、その描画の Requirements を書くときに所有者が決める。それまでは、ソースのテキストのまま見せる。順序を変えても、保存された本文と辺の規則は変えない。

Gyazo バケット `gyazo-archives` の請求上の使用量は、まだ測っていない。上の 26.3 GiB は、ローカル展開の大きさである。請求額ではない。所有者が測るまで、請求上の大きさは書かない。この未測は、画像 URL を変えない。月 10 GB を超える保存は、ゼロ円の対象外のままである。
